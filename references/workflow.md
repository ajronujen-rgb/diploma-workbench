# Рабочий цикл

1. Codex читает компактное состояние и классифицирует задачу.
2. Для содержательной задачи сначала запускается AUTHOR-FIRST, но не AUTHOR-ONLY: обычный ChatGPT извлекает только достаточную исходную позицию автора до подробной теоретической рамки и, если возможно, до подбора основного корпуса источников. Неизвестность автора фиксируется как `OPEN_QUESTION`, а не вытягивается интервьюированием. Позиция хранится в `01_понимание_задачи/AUTHOR_POSITION.md` как рабочая до проверки источниками.
3. Для A/B Codex обновляет локальные файлы пакетно, не затрагивая оригиналы. Для C он формирует `CHATGPT_HANDOFF` с явным режимом AUTHOR-FIRST; обычный ChatGPT работает с автором и выдаёт `CODEX_RETURN`.
4. STOP RULE первичного интервью: после каждого содержательного блока определить, требует ли следующий разумный шаг литературы. Если да, зафиксировать `AUTHOR_POSITION v0` и `OPEN_QUESTIONS`, проверить резюме у автора и завершить интервью.
5. Итеративный цикл: `AUTHOR_POSITION v0` → `OPEN_QUESTIONS` → релевантная литература → точное установление сказанного источником → реакция автора только в значимых точках → уточнение или изменение позиции → следующий источник либо вопрос.
6. Пробелы различаются так: `AUTHOR_GAP` уточняется интервью, `RESEARCH_QUESTION` остаётся открытым для исследования, `LITERATURE_DEPENDENT` требует перехода к источникам.
7. Если `LITERATURE_DEPENDENT` требует выбора корпуса, сначала выполни: `ACADEMIC_FIELD_MAPPING` → `CANDIDATE_APPROACHES` → `SELECTION_CRITERIA` → `SELECTED_APPROACHES` и существенные `EXCLUDED_APPROACHES` → `REPRESENTATIVE_PRIMARY_SOURCES` → проверка первичных текстов. Сохрани это в `02_источники/карта_области.md`. Не повторяй mapping, если в проекте есть релевантная проверенная карта; не устраивай искусственный конкурс для однозначно необходимого источника.
8. До необратимого сбора или анализа основных результатов выполни ANTI-SELECTION-BIAS CHECKPOINT, если выбор единиц анализа способен повлиять на вывод: критерии, пространство кандидатов, включённые/исключённые/пограничные элементы и независимое основание для ранее выделенных автором элементов. Сохрани проверку в `01_понимание_задачи/чекпоинт_отбора.md`.
9. Codex принимает возврат из чата или `inbox/pending`, валидирует, ищет конфликт с паспортом, решениями, статусами и замороженными материалами.
10. Допустимое интегрирует в производные файлы; конфликтное переносит в `inbox/needs-decision` и объясняет, что требуется решение человека. `AI_SUGGESTION` не интегрируется как `AUTHOR` без собственной переработки автора.
11. Codex сохраняет историю возврата, обновляет `PROJECT_STATE.md`, журнал работы и при необходимости журнал решений.
12. После стабилизации смысла и до редакторского конвейера приводит финальный русскоязычный текст к принятой терминологии: сохраняет необходимый оригинал при первом введении, затем использует выбранный русский эквивалент последовательно.
13. Когда собран полный итоговый текст диплома, авторские содержательные решения получены и не нужно новое исследование, агент сам запускает внутренний редакционно-контрольный pipeline по `references/internal-editorial-qc.md`. Не запускает полный pipeline для карточек, возвратов, заметок, фрагментов и промежуточных глав без явного запроса автора. Внешний handoff на этой стадии запрещён для применения доступных skills.
14. При исправимом дефекте применяет результат в пределах контракта skill и повторно проверяет только затронутый аспект. При обнаружении нового содержательного решения, неразрешённого факта или авторски чувствительной правки возвращается к соответствующей предыдущей стадии, а не передаёт редактуру наружу.
15. До выпуска финального файла сверяет оформление по методичке вуза. Пока её нет, заполняет `09_финал/чеклист_оформления.md` по временной базе ГОСТ; не выдаёт такую проверку за подтверждение требований кафедры.

После конвейера человек сверяет источник, страницу, дословность цитаты, выводы из данных, авторство собственного вывода и методичку.
