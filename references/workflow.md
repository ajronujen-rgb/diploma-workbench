# Рабочий цикл

1. Codex читает компактное состояние и классифицирует задачу.
2. Для содержательной задачи сначала запускается AUTHOR-FIRST: обычный ChatGPT извлекает исходную позицию автора до подробной теоретической рамки и, если возможно, до подбора основного корпуса источников. Позиция хранится в `01_понимание_задачи/AUTHOR_POSITION.md` как рабочая до проверки источниками.
3. Для A/B Codex обновляет локальные файлы пакетно, не затрагивая оригиналы. Для C он формирует `CHATGPT_HANDOFF` с явным режимом AUTHOR-FIRST; обычный ChatGPT работает с автором и выдаёт `CODEX_RETURN`.
4. Цикл источника: источник → точное установление сказанного источником → вопросы автору о связи с его позицией → собственная реакция автора → уточнение мысли и проверка логической связи → промежуточный тезис с происхождением.
5. Codex принимает возврат из чата или `inbox/pending`, валидирует, ищет конфликт с паспортом, решениями, статусами и замороженными материалами.
6. Допустимое интегрирует в производные файлы; конфликтное переносит в `inbox/needs-decision` и объясняет, что требуется решение человека. `AI_SUGGESTION` не интегрируется как `AUTHOR` без собственной переработки автора.
7. Codex сохраняет историю возврата, обновляет `PROJECT_STATE.md`, журнал работы и при необходимости журнал решений.
8. По завершении смысловой части запускает конвейер: Чуковский → Аграновский → Слопотрон → Розенталь → Мильчин.

После конвейера человек сверяет источник, страницу, дословность цитаты, выводы из данных, авторство собственного вывода и методичку.
